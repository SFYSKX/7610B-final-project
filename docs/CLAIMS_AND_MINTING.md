# 用户申诉与网页铸造

本次只调整分工第 3 项（申诉）和第 12 项（铸造）。账户连接、买卖、竞拍、手续费和原多签审批方式沿用现有实现。

## 用户申诉

1. 管理员注资，通过原多签流程开放事故及预算，公布事故 ID、政策与截止时间。
2. 普通用户连接自己的钱包，打开“我的申诉”，填写事故 ID、关联订单/拍卖/交易记录、申请金额、原因及证据说明或链接。
3. 用户自己签名提交，直接进入“待审核”。无需管理员先登记用户资格，管理员也不能代用户提交。链上受益人固定为发送交易的账户。
4. 管理员在“风险准备金”查看申请原文和证据摘要，在“共同管理”选择批准或拒绝，沿用 LocalCouncil 2/3 或 Sepolia Safe 原审核流程。
5. 批准金额必须大于零、不超过申请金额，事故累计批准不得超过预算。获批用户自己领取；拒绝显示理由摘要。

每个账户对同一事故只可提交一次，拒绝后也不能重提；有独立的新事故时可以再次申请。不同用户可以填写相同关联记录，不能通过抢先提交阻止真正申请人；审核者仍需人工识别重复损失和多账户滥用。申请不是损失真实性证明，也不保证获得赔付。普通用户不能创建任意无预算工单。

关联记录、原因和证据说明以正文公开上链，合计不超过 1024 个 UTF-8 字节；证据输入同时生成 hash。不要在表单中填写个人秘密。政策和拒绝理由仍只保存摘要，应另行保存正文。暂停阻止新增申诉，已批准领取不受暂停或事故关闭影响。截止、预算、拒绝和转账失败的原有检查仍有效。

接口为 `submitClaim(incidentId, lossKey, requestedAmount, statement, evidenceHash)`。旧 `registerEntitlement` 已移除；`maxLoss` 字段保留名称但表示用户申请金额，`Registered` 枚举槽保留数字兼容，当前流程不再产生该状态。

## 网页铸造

NFT 集合的实际 `owner()` 连接后显示“铸造管理”，选择已配置集合，填写接收地址和数量即可签名发行，无需运行命令。发行权与平台 Safe 管理权限独立；普通 Safe 签名者不会自动获得 NFT 铸造权。

新版 DemoNFT 支持一笔 `mintBatch` 交易发行 1–10 件，连续分配 Token ID，任意一件交付失败则整笔回滚。数量为 1 时仍调用原 `mint`。旧版仅支持原接口的 DemoNFT 每次限 1 件；不兼容的外部集合不显示发行入口。RPC 读取失败不会被当作权限已确认。

### 填写 NFT 内容

发行者可填写 NFT 名称、描述、HTTPS／IPFS 图片链接。名称为必填项，其余内容可选。预览复用详情读取器的字段转换规则。

名称、描述和图片引用会按 ERC-721 元数据字段 `name`、`description`、`image` 编码为 UTF-8 Base64 JSON，传给现有 `mint` 或 `mintBatch` 接口。网页按最终 tokenURI 的字节数校验 4096 字节上限，超限时需要缩短内容。中文和表情按实际编码长度计算。

图片链接应直接指向公开图片，例如 `https://example.org/art.png` 或 `ipfs://<CID>/art.png`。HTTPS 由原站提供图片，IPFS 通过详情组件配置的公共网关读取。图片预览失败时请检查链接；铸造保存的是填写的链接。此表单提供图片链接输入。

同一批 NFT 共用填写的内容，链上 Token ID 各不相同。需要不同内容时，分别提交铸造。选择其他集合会更新接收地址和数量表单，并保留当前内容草稿供核对。

铸造确认后，切换到接收账户，在“我的资产 → 查看 NFT 详情”核对图片、名称和描述。创建挂牌或拍卖后，相应页面通过同一个 tokenURI 展示详情，名称搜索也会读取其中的 name。编号和归属还可在链上 Transfer 事件核对。看到待确认或未知结果时先检查回执。

此次内容编辑使用现有 NFT 合约的 URI 接口，适用于当前单件和批量铸造集合。


## 部署兼容性

RiskReserve 的业务 API 从 2 改为 **3**，其他业务合约仍为 2；部署清单的 `apiVersion: 2` 继续表示清单格式。连接和部署校验会拒绝旧准备金，避免用新 ABI 操作旧合约。

现有合约没有代理升级，FeeRouter 绑定准备金也只能执行一次。因此应在新的独立部署中重新部署整套平台，再配置新清单与 Safe 权限；单改前端或替换准备金地址不能迁移旧绑定。旧资产、资金、领取权不会自动迁移，应从旧部署完成领取。需要批量铸造时同时部署新版 DemoNFT；旧 NFT 的单件发行仍可使用。

本地运行 `npm run demo` 会使用新合约。Sepolia 必须按独立部署指南创建新部署请求，不能删掉未完成部署记录来重发交易。提交功能前先跑 `npm test`、`npm run build` 和本地流程，再由组员在自己的测试网实例验收。

## 手动验收

- 发行账户铸造 2 件给卖方，核对编号及归属；另一个管理员不显示发行入口。
- 开放事故，普通用户直接提交，确认无需预登记；同账户同事故重复提交应失败。
- 管理员不能提交用户申诉；其管理菜单保留预算、批准及拒绝，不再有资格登记。
- 两位管理员完成批准，用户领取并显示“已支付”；重复领取失败。
- 换另一普通用户提交后拒绝，核对原因摘要。检查超期、无预算、超额和暂停情况。
- 切换交易市场、我的资产和公开拍卖，确认原页面与功能仍可进入。
