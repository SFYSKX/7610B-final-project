# 本地逐功能测试

## 前置条件

按 [安装说明](SETUP.md) 完成 `npm ci` 和 `npm run demo`，打开输出的网页地址，点击“本地演示”。本地完整演示已包含自动结算。保持启动终端运行，不同时执行会改变同一条链的 smoke 测试。

账户使用 [账户表](ACCOUNTS.md) 的索引：0/1/2 为管理者，3 为卖家 S，4 为买家 X，5 为竞价者 Y，9 为 Keeper。全新 demo 中 S 持有 NFT 1、4，X 持有 2、5，Y 持有 3、6。不要假定所有 NFT 都属于卖家。

集合地址从“我的资产 → 支持的集合”读取，或查看 `deployments/31337.json` 的 `collections`。每笔操作确认后再切换账户；记录实际订单、拍卖、事故和权益 ID。

## 1. 资产显示与授权

1. 连接 S，进入“我的资产”，确认看到 1、4。
2. 选择 NFT 1，检查下方集合地址和 Token ID 自动填入。
3. 授权用途选“交易市场 Marketplace”，确认目标合约名称与地址，点击授权。
4. 等待状态变成已授权；NFT 仍属于 S，授权本身不会创建订单。
5. 拍卖使用“拍卖市场 AuctionHouse”。将单件授权改给另一个市场后，原单件授权会被替换。

## 2. 定价购买和调价

1. S 使用已授权的 NFT 1，价格填 `0.001`，有效小时填 `24`，点击“托管 NFT 并挂牌”。
2. 到“交易市场 → 我的挂牌”记录订单 ID，NFT 此时托管在 Marketplace。
3. 展开调价表单，改为 `0.0012`、24 小时，确认订单价格和版本号更新。
4. 切 X，找到该订单并购买。检查 X 的“我的资产”出现 NFT 1，订单显示已成交。
5. 切 S，在“我的卖款”领取到 S。默认 1% 费率下净卖款为 `0.001188`，平台费为 `0.000012`。
6. 确认可领取卖款归零，已成交订单无法再次购买。

浏览器钱包模式可以先在钱包拒绝一次购买，再核对订单未成交；本地解锁账户模式没有 MetaMask 签名弹窗。

## 3. 撤单

S 用 NFT 4 授权、挂牌后，在“我的挂牌”点击“撤单并取回”。预期订单已撤销，NFT 4 回到 S，其他账户不能购买此订单。后续可复用 NFT 4。

## 4. 拍卖、错误提示和退款

1. S 选择 NFT 4，先只授权 Marketplace，再尝试创建拍卖；创建表单应提示需要 AuctionHouse 授权，资产不应被转走。
2. 改授 AuctionHouse，底价 `0.001`、最小加价 `0.0001`、持续 `5` 分钟，创建拍卖并记录 ID。
3. X 先输入 `0.0005`，应在报价表单附近收到中文低报价提示；再输入 `0.001` 成功出价。
4. Y 输入完整报价 `0.0011`。不能只支付差额 `0.0001`。
5. X 在“我的拍卖资金”领取 `0.001` 退款，退款余额应清零。
6. 等到期，后台由索引 9 自动结算。界面短暂等待后应显示已结算。
7. Y 在卡片中领取 NFT 4，S 领取拍卖卖款。默认费率下卖款为 `0.001089`，手续费为 `0.000011`。

结算和领取是分开的交易。已出价拍卖不能由卖家取消，非权益人不能领取赢家 NFT。

## 5. 无人出价和取消拍卖

X 可以作为卖家使用自己仍持有的 NFT 2：授权 AuctionHouse，创建 2 分钟拍卖，不出价，到期自动结算后由 X 领取。

Y 使用自己持有的 NFT 3 创建拍卖，在没有出价时点击“取消无出价拍卖”。取消后继续点击“领取 NFT”，资产才返回 Y。记录这与定价撤单直接返还的区别。

## 6. 手续费分配

切管理者 0，进入“共同管理 → 手续费归集”。依次执行市场费归集、拍卖费归集、准备金入账、经营收入支付。每笔确认后观察余额。

若只有上述两笔成交，平台总费应为 `0.000023`，准备金和管理金库各 `0.0000115`。接收地址固定；执行者不会取得资金。普通用户不应看到管理入口。手续费归集可以由一名当前管理员直接执行。

## 7. 本地多签和风险赔付

1. 管理者 0 在“风险准备金”注资 `0.01`。
2. 在“共同管理”选择“准备金：登记事故预算”，填写模拟政策正文，预算 `0.005`，申请窗口 `30` 分钟，审核窗口 `60` 分钟。
3. 生成操作预览并提出提案。提出者自动一票，此时不可执行。
4. 切管理者 1，批准同一提案，达到两票后执行。记录事故 ID；事故预留增加 `0.005`，可分配减少同额。
5. 多签登记 X 的权益：事故 ID 使用实际值，损失标识如 `SIMULATED local case01 claimant01`，受益人填页面显示的 X 地址，上限 `0.002`。不要填账户索引代替地址。
6. X 进入“我的赔付”，找到权益并提交证据说明。状态应从已登记变为待审核。
7. 多签批准该权益 `0.0015`，X 再领取，状态变为已支付。不能重复领取。
8. 为 Y 登记另一个唯一损失标识的权益，让 Y 提交申请，再通过多签拒绝并填写理由。Y 应看到已拒绝和理由摘要。
9. 审核截止后，管理员在事故行释放未批准预算。仅批准上述金额时释放 `0.0035`；已批准未领取的部分继续保留领取权。

政策、证据和拒绝理由会转换为 hash，保存测试正文以便对照。两次截止均从生成预览时的区块时间计算，提案等待期间时间仍会流逝。

## 8. 单件禁用与集合许可

1. 选当前仍由普通用户持有的 NFT 5，记录其集合和持有人。
2. 管理者通过多签选择“拍卖：禁用或恢复单件 NFT”，填该集合、Token ID 5、`true`。
3. 持有人授权后尝试创建拍卖，应被拒绝；同集合 NFT 6 应不受影响。
4. 把 NFT 5 设置为 `false` 并执行，重新创建应成功。
5. 对交易市场的单件禁用做同样测试。两个市场分别维护规则。
6. 若测试整个集合停用，使用“启用或停用整个集合”，确认影响集合的新增托管，随后恢复为 `true`。

退出测试后取消无出价测试拍卖并领取 NFT。单件禁用不应阻止既有退款、取消、结算或领取。

## 9. 费率快照和暂停

在 100 bps 下创建一个订单，随后由多签把未来订单费率改为 200 bps。旧订单应保留 1%，新订单采用 2%；修改旧订单价格也不改变其费率快照。拍卖同理。测试完将两项费率恢复为 100，取消对照订单/拍卖并取回资产。

分别通过多签暂停市场、拍卖和准备金，验证新增业务受限，已有退款、卖款、NFT 和获批赔付的领取仍可执行。测试领取出口时先准备相应尚未领取的权益。然后将暂停状态全部恢复为 `false`。

## 10. 记录、查询与角色隔离

分别切普通账户检查菜单，无“风险准备金”和“共同管理”；切管理员应显示。普通账户在“交易记录”只看到自己在本浏览器的操作；管理员能看到本浏览器当前部署的各账户记录。

在“资产溯源”按集合与 Token ID 查询，检查托管、成交和普通转移的分类。普通账户只显示本人参与的相关事件；管理员可查看完整资产履历。尝试 CSV 导出与“加载更早 2,000 个区块”。使用订单/拍卖/事故/权益的按 ID 查询入口核对较早记录。

记录实际结果，模板见 [验证文档](VALIDATION.md)。超时先检查交易回执，不能直接重复发送；复杂拒收、重入和精确边界由自动化测试补充。
