# 登录与角色分流

## 使用方式

首次打开、刷新或退出后，先显示独立登录页。选择“用户入口”或“管理员入口”，再连接 MetaMask。连接和身份核验成功后才显示业务导航。用户端默认进入交易市场，管理端默认进入共同管理。

启动 `npm run demo` 后，也可以展开登录页的“本地演示”：用户入口提供索引 3–8 的交易和备用账户，管理员入口提供索引 0–2 的管理签名者。索引 9 是 Keeper 专用账户，不列入登录选项。账户分组便于演示，实际权限仍逐次从链上读取。

“连接钱包进入”使用 MetaMask 当前网络的 RPC，不会自动改用本地演示节点。“本地演示”才会读取 `public/deployments/31337.json` 中的 `localRpcUrl`。例如隔离演示节点使用 `18545` 时，仍连接默认 `8545` 的 MetaMask 会失败；可直接使用本地演示，或手动将钱包本地网络设为清单中的 RPC、Chain ID `31337`、货币符号 `ETH`。Sepolia 需先完成独立部署，只有钱包并不能创建平台。登录失败提示与交易失败提示分开；登录仅连接、读取，不发送交易。

管理员可以切换到用户工作区，再通过“进入管理端”返回；每次切换重新连接并核验。用户视图不展示管理菜单和跨账户浏览器记录，但不会改变地址的实际权限：管理员仍不能提交用户申诉。NFT 铸造权限单独读取，平台管理员不会因此自动取得发行权。

## 身份与权限

本项目以钱包作为账户，没有账号密码数据库、服务端登录令牌或注册流程。连接钱包、读取身份不发送链上交易；业务交易继续由钱包签名。这里的“登录”是前端工作区准入，链上合约仍负责最终授权。

- 本地核验 `LocalCouncil.isSigner(address)`，Sepolia 核验当前 Safe 的 `isOwner(address)`；沿用原有管理合约地址本身的管理员识别规则。
- 选择管理员入口不会赋予权限。普通地址误选时留在登录页，可以切换钱包或改选用户入口。
- 核验使用同一区块。身份读取失败、超时或返回无效结果时，两类入口都不会放行。
- 工作区持续读取身份；读取失败时暂停整个工作区，恢复后重新展示。管理员资格被撤销时返回登录页。
- 钱包切换账户、网络或断开连接时，立即清除当前前端会话，重新选择入口并核验；延迟返回的旧连接或旧查询不能重新打开工作区。
- 刷新不自动登录，浏览器中的角色偏好不能替代链上核验。

退出只结束本网页会话，不撤销 MetaMask 对站点的连接许可，不撤销 NFT 授权，也不撤销已经广播的链上交易。待确认交易、操作日志和资产关注记录继续按原部署和账户保存，重新连接原账户后可恢复查询。交易正在提交时禁用主动退出；钱包事件仍会立即收起旧工作区，原交易继续记录到原账户。

## 验收

1. 打开或刷新网页，应只见登录页，不出现业务侧栏；旧版自动恢复本地账户的记录不能绕过登录。
2. 用户入口 → 本地演示 → 卖方：默认进入交易市场，不显示共同管理和风险准备金。切买方、竞价者，确认资产和记录随账户变化。
3. 退出 → 管理员入口 → 本地演示 → 管理签名者 1：默认进入共同管理，优先展示管理菜单；签名者 1 可见铸造入口，签名者 2 不可见。
4. 管理员切换到用户端：管理菜单隐藏，记录仅显示当前账户；申诉仍提示管理员使用审核流程。
5. MetaMask 使用普通地址选择管理员入口：提示没有权限，不进入管理端；改选用户入口可进入交易端。
6. 连接后在钱包中切换账户、网络或断开：立即返回登录页，旧管理员页面消失。核验中取消登录后，迟到结果不能恢复旧会话。
7. 模拟身份 RPC 失败或超时：不能将未知身份当作普通用户放行；登录后失败也会暂停工作区。
8. 存在待确认交易时退出再登录同账户：恢复待确认提示，不能重复发送原交易。

自动检查执行 `npm test` 和 `npm run build`。登录服务、工作区准入、页面菜单、会话切换及预检期间失效的交易分别有客户端回归测试。MetaMask / Sepolia 的真实钱包交互仍需按上述步骤验收。

管理员入口仅允许本平台已有的链上管理员进入。新建的个人 MetaMask 钱包不会自动成为管理员；本地验收可以展开“本地演示”，选择“管理签名者 1”后进入管理工作区。
