# 项目介绍与业务流程

## 1. 这个项目用来做什么

Ledger Market 是一个 NFT 交易与风险准备金的教学 DApp。它让用户在自己的钱包控制下出售、购买和竞拍 NFT，并用链上规则记录托管资产、应付卖款、竞价退款、平台手续费和赔付预算。管理者通过多人审批调整平台规则、分配事故预算和审核赔付。

项目把交易和管理流程放在一起，便于理解：用户授权后资产在哪里、付款后谁能领取资金、一次成交怎样产生平台收入、平台怎样预留赔付预算，以及管理员之间如何共同批准操作。它适用于本地课程演示、多人测试网实验和开发调试。运行在 Sepolia 时，业务使用 SepoliaETH；本地链使用节点提供的虚拟 ETH。

接收者既可以在本机模拟全部角色，也可以部署自己的 Sepolia 实例，让其他参与者用各自的钱包交易。每个独立实例都有自己的合约、集合、管理员、余额和业务记录。包内没有预置作者的账户或部署状态。

## 2. 理解页面前的几个概念

| 概念 | 在本项目中的含义 |
|---|---|
| NFT | ERC-721 合约中的一件独立资产，用于测试持有、授权、托管和交易 |
| 集合地址 + Token ID | 一件 NFT 的完整身份；同集合内编号不同，跨集合相同编号也不是同一资产 |
| 授权 | 持有人允许指定市场合约转移 NFT；授权不会立即出售资产，也不会同时授权两个市场 |
| 托管 | 创建订单或拍卖时，NFT 转入对应合约，之后按成交、取消或领取规则转出 |
| 订单 / 拍卖 ID | 业务记录的编号，与 NFT 的 Token ID 不同，查询时不能混用 |
| 可领取余额 | 合约已经记给某账户、但尚未实际转出的款项，需要权益人发送领取交易 |
| 多签 | 达到规定数量的管理员批准后，由管理合约执行一笔操作 |
| Safe | Sepolia 使用的外部多签账户工具；本项目的管理合约地址设为接收者自己的 Safe |
| Keeper | 持续检查到期拍卖、用专用账户提交结算交易的程序，不负责认定赔付或任意改变成交结果 |
| 事故预算 / 赔付权益 | 一项事故预留的资金上限，以及用户自主提交、经审核批准后的领取权；提交不等于批准付款 |
| Gas / 平台手续费 | Gas 支付链上交易执行成本；平台手续费从成交金额中按规则扣除，两者分别计算 |

随包的 DemoNFT 是供发行者铸造的测试集合。测试 NFT 的编号和交易事件并不证明现实物品的所有权或价值。界面中的“我的资产”主要展示配置清单中的集合，不能理解为扫描钱包持有的全部公链 NFT。

## 3. 参与者与责任

| 参与者 | 主要工作 | 不由这个角色单独决定的事项 |
|---|---|---|
| 部署者 / 测试资产发行者 | 部署合约、维护公开清单、向测试参与者铸造 DemoNFT | 部署行为本身不赋予 Safe owner 身份 |
| 卖家 | 选择资产、授权、挂牌或发起拍卖、领取卖款 | 不能取消已经有人出价的拍卖 |
| 买家 / 竞价者 | 购买、出价、领取退款或获胜 NFT | 不能领取其他账户的资产和资金 |
| 管理签名者 | 共同审核配置、预算与赔付；执行获准的固定方向维护操作 | 多签票数不能绕过余额、截止时间和合约状态检查 |
| 赔付受益人 | 对开放事故自主提交原因及证据，获批后领取 | 不能超出事故预算或批准自己的赔付 |
| Keeper 运营者 | 维持服务、RPC 和专用账户 Gas 余额，观察结算状态 | 服务不能自由选择赢家或改变既有报价 |

普通用户默认看到交易市场、我的资产、公开拍卖、资产溯源、交易记录和我的申诉。管理员还看到风险准备金、共同管理。角色隐藏属于界面体验，实际权限同时由合约校验；公链数据不会因为界面过滤而变成私密信息。

## 4. 各页面提供什么

### 我的资产

查看支持集合中的持仓，选中 NFT 后带入集合地址和编号。用户选择授权给 Marketplace 或 AuctionHouse，再去相应业务中创建订单。两个合约各自需要授权，单件授权改授另一个目标会替换原目标。授权状态支持分别取消市场权限或一键取消两个市场；单件授权使用 approve(零地址) 撤销，集合级操作员授权使用 setApprovalForAll(operator, false) 撤销。

### 交易市场

卖家设置价格和有效期，创建托管订单；可以更新订单或撤单取回资产。买家按当前订单版本和价格购买，NFT 交付到指定接收者，净卖款记入卖家的可领取余额。订单版本检查用于避免用户按旧价格信息误买已经修改的订单。

### 公开拍卖

卖家设置底价、最小加价和结束时间。首次出价至少达到底价，后续出价至少达到当前最高价加最小加价；每次提交完整报价。被超价的资金变为可领取退款。

拍卖到期后，在线 Keeper 提交结算交易。有人出价时确立赢家的 NFT 领取权和卖家的净卖款；无人出价时确立卖家取回 NFT 的权利。结算与领取是不同步骤。无出价拍卖可以取消，取消后仍需领取 NFT。

### 资产溯源和交易记录

资产溯源按集合与编号查询 Transfer 和当前部署的成交事件，可加载较早区块并导出 CSV。外部转移没有可识别成交事件时，不推断成交价。

交易记录用于查看当前浏览器保存的操作与交易状态，支持处理待确认交易。普通账户只显示自己的记录，管理员可查看本浏览器中当前部署的各账户记录；换电脑后不会自动同步完整记录。

### 风险准备金和我的申诉

管理员查看准备金余额、预留预算和事故状态，并进行获准的注资或预算释放。普通用户在“我的申诉”对开放事故自主提交申请并领取获批款项，无需预登记。申诉正文与证据摘要上链，政策和拒绝理由仍仅存摘要。NFT owner 可以通过“铸造管理”填写接收者和数量发行资产。

### 共同管理

提供集合许可、单件 NFT 禁用、费率、暂停、Keeper 配置和赔付相关管理操作。可以限制整个集合，也可以只限制某集合中的指定 Token ID；市场与拍卖分别维护限制。

本地由 LocalCouncil 完成提案、批准和执行。Sepolia 的多签操作由 DApp 生成预览和 Safe JSON，再在 Safe 中批准、执行。费用归集、固定方向分账等部分维护动作允许一名当前管理员直接执行，具体见 [权限表](ACCOUNTS.md)。

## 5. 三个完整业务示例

以下数字用于说明规则，不代表已经存在的订单或资金。每笔链上写操作都可能另付 Gas。

### 示例一：固定价格卖出一件 NFT

1. 卖家持有一件 NFT，授权 Marketplace，按 `0.01 ETH` 挂牌；NFT 进入市场合约托管。
2. 买家支付 `0.01 ETH` 完成购买，NFT 交付买家指定接收者。
3. 默认费率为 1%，卖家得到 `0.0099 ETH` 可领取卖款，市场累计 `0.0001 ETH` 平台费。
4. 卖家发送领取交易，把净卖款转出。
5. 管理员归集平台费并执行分账：默认 `0.00005 ETH` 进入准备金，`0.00005 ETH` 进入固定管理金库。

费率在订单创建时记录为快照。之后调整平台费率，不会追溯修改已有订单的费率。

### 示例二：两人竞拍

卖家发起底价 `0.01 ETH`、最小加价 `0.001 ETH` 的拍卖。竞价者甲支付 `0.01 ETH`，乙随后支付完整的 `0.011 ETH`。甲可以领取自己的 `0.01 ETH` 退款。

到期后 Keeper 提交结算。乙随后领取 NFT；默认 1% 费率下，卖家可领取 `0.01089 ETH`，拍卖合约累计平台费 `0.00011 ETH`。Keeper 支付结算交易的 Gas，卖家和赢家分别支付自己的领取交易 Gas。

如果 Keeper 离线，到期只表示拍卖不再接受有效出价，链上结算不会凭空发生；恢复服务后再提交结算，或由管理合约应急执行。结算到账时间还取决于 RPC、网络和区块确认。

### 示例三：模拟损失申请赔付

1. 准备金总余额为 `0.01 ETH`，没有其他预留。管理员通过多签为模拟事故登记 `0.005 ETH` 预算和期限。
2. 预算被预留，可分配余额降为 `0.005 ETH`，合约总余额仍为 `0.01 ETH`。
3. 普通用户在截止前自主提交 `0.002 ETH` 申诉，填写关联记录、原因和证据，无需管理员预登记。
4. 管理员共同审核并批准 `0.0015 ETH`。受益人领取后，总余额变为 `0.0085 ETH`，本事故尚余预留 `0.0035 ETH`。
5. 若没有其他批准，在审核截止后关闭事故，释放 `0.0035 ETH`，可分配余额变为 `0.0085 ETH`。

若款项已经批准但尚未领取，关闭事故仍保留这部分资金供受益人领取。不同事故各有预算，同一事故累计批准额不得超预算。卖款和退款保存在各自交易合约中，不能拿来充当事故预算。

## 6. 各部分如何配合

| 部分 | 承担的职责 |
|---|---|
| React + Vite 网页 | 展示数据、收集输入、业务预检、中文错误提示、连接钱包和追踪交易 |
| Solidity 业务合约 | Marketplace 管定价交易；AuctionHouse 管竞拍；FeeRouter 管分账；RiskReserve 管预算与赔付 |
| MetaMask + RPC | 钱包确认用户交易；RPC 提供链上读取、广播和回执查询 |
| LocalCouncil / Safe | 分别用于本地和 Sepolia 的多人管理授权 |
| Node.js Keeper | 在浏览器之外持续检查到期拍卖，并提交授权范围内的结算交易 |
| 部署与测试脚本 | 编译、部署、发行测试资产、初始化本地数据、验证配置与自动化验收 |

核心业务状态在链上，网页本地记录在浏览器，部署地址在按网络生成的 JSON 清单中。没有保存所有历史事件的独立数据库服务。模块接口和故障边界见 [架构说明](ARCHITECTURE.md)。

## 7. 本地体验与 Sepolia 体验

| 对比项 | 本地实验 | Sepolia |
|---|---|---|
| 目的 | 快速理解功能、切换角色、验证异常与边界 | 验证真实钱包、多签、公共 RPC 和交易确认过程 |
| 账户 | 节点提供的公开测试账户，网页可切换 | 接收者和其他参与者自己的钱包 |
| 资产与资金 | demo 创建测试 NFT 和虚拟 ETH | 自己部署集合、铸造资产并准备 SepoliaETH |
| 多签 | LocalCouncil，在 DApp 中操作 | 自己的 Safe，管理 JSON 在 Safe 执行 |
| 时间与持久性 | 内存链，停止后状态丢失；专用测试可快进 | 等待公共链时间，已确认交易持续存在 |
| 自动结算 | 一键 demo 包含 Keeper | 部署方单独运行 Keeper 并补充测试 Gas |

首次阅读者建议先走一次本地业务流程，再决定是否准备 Sepolia 账户。普通用户加入别人已部署的平台只需前端入口、相应网络的钱包和测试资金；只有要建立自己的独立平台时，才需要执行整套部署。

## 8. 当前实现边界

申诉面向管理员已开放的事故，无需预登记资格；不支持任意无预算工单，也没有自动判定现实损失的机制。准备金受余额和预算约束，不能保证所有申请都会获赔。

合约不自动定时运行；Keeper 必须在线。拍卖结算不会代替用户领取 NFT、卖款或退款。暂停和禁用保留既有退出、退款和领取通道，但不能把已经确认的历史成交撤销。

资产查询存在集合与数量限制，历史事件分批扫描，浏览器日志不等于全链数据库。页面权限过滤不会改变公链数据公开性。合约没有代理升级机制，修改链上业务规则需要新部署；已有资产和余额不会自动迁移。

本项目用于教学和测试网实验。自动化测试证明的是已覆盖用例的行为，不等于已完成生产安全审计。
